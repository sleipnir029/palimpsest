# T20.5 — central normalize.py + per-skill normalization.yaml overlay

## Why
Per-skill normalization rules (canonical units, categorical enums, operating-point
buckets) duplicate the universal physics-of-electrochemistry across every future
SKILL.md (HER, CO2RR, NRR). Universal-vs-domain belongs in **two layers**, not in
each SKILL.md body. Without this, T22 (extraction) reinvents normalization
mid-flight per domain and silently drifts.

Surfaced during T20 review: SKILL.md prose teaches the LLM *what* to record, but
nothing centralizes *how* — units, enums, buckets. This task fixes the gap.

## Input state
- T20 merged. `skills/oer-extraction/SKILL.md` exists.
- Schema (T18) has free-text `unit_label` on `Measurement`; no enums for
  `iR_correction`, `normalization_basis`, `cell_type_family`, etc. (Schema-level
  enums stay deferred to T18a; this task is prompt-side normalization only.)

```python
# Universal canonical units (palimpsest's preferred form per slot).
# Any other form must be converted by the LLM before emission.
UNIVERSAL_UNITS: dict[str, str] = {
    "overpotential": "mV",
    "tafel_slope": "mV/decade",
    "mass_activity": "A/g",        # per active metal; domain names which
    "ecsa": "m2/g",                # specific ECSA; geometric ECSA is cm2
    "exchange_current_density": "mA/cm2",
    "stability_hours": "h",
    "pemwe_cell_voltage": "V",
    "current_density": "mA/cm2",   # canonical; A/cm2 also accepted, see below
    "temperature": "C",
    "pressure": "bar",
}

# Universal categorical enums (apply to every electrochemistry domain).
# Domain overlays may add buckets but MUST NOT redefine these.
UNIVERSAL_ENUMS: dict[str, list[str]] = {
    "iR_correction": ["applied", "not_applied", "unknown"],
    "normalization_basis": ["geometric", "ECSA", "BET", "mass"],
    "cell_type_family": ["RDE", "three_electrode_flow", "single_cell_MEA", "stack"],
    "electrolyte_family": ["acid", "alkaline", "neutral"],
    "scan_rate_regime": ["steady_state", "slow_LSV", "fast_LSV", "fast_CV"],
}

def load_skill_normalization(skill_dir: Path) -> dict:
    """Read skill_dir/normalization.yaml if present; return {} otherwise."""

def build_normalization_prompt(active_skill_dirs: list[Path]) -> str:
    """Merge UNIVERSAL_* with each active skill's normalization.yaml.
    Return a markdown block to inject into the LLM system prompt.

    Conflict policy: if a domain overlay defines an enum that's already in
    UNIVERSAL_ENUMS, raise loudly. Universal is the source of truth.
    """
```

## Out of scope
- Unit-conversion engine (e.g. `convert_unit(1, "V/dec", "mV/dec") -> 1000`).
  Canonical-unit declaration is enough for the LLM to convert at extraction
  time. If post-hoc validation is needed later, add a small `pint`-based
  converter or a hand-rolled lookup — **separate** task.
- Per-skill normalization for HER / CO2RR / NRR. Those land with the
  respective `skills/<domain>/normalization.yaml` files when those domain
  skills are written.
- LinkML enum classes for universal categoricals (`iR_correction`, etc.).
  Schema-level validation belongs in T18a.
